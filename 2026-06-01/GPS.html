1 方案總覽

使用者輸入「影片中是否有異常」等模糊問題時，以下六個層面可以提升系統效果：

方案 複雜度 效果 適合時機
System Prompt 強化 低 中高 第一步，必做
Structured Output (JSON) 低 高 需要程式處理結果時
Chain-of-Thought 引導 低 高 複雜場景判斷
Few-shot 示例注入 中 高 有標註好的案例時
多幀 / 關鍵幀分析 中 高 長影片
多步驟 Agent Pipeline 高 最高 準確率要求高
💡 System Prompt + 幀採樣調整 是成本最低、效果最顯著的起點，建議優先實作這兩項再評估是否需要更複雜的架構。

2 System Prompt 設計策略

🎭 角色設定
必要
告訴模型它是安全專家，不是通用助手。角色設定會影響模型的注意力分配。
📋 違規清單
必要
明確列出要偵測的行為類型（尾隨、未刷卡進入等），避免模型自行定義「異常」。
🔍 思考步驟
建議
強制模型先描述場景、再判斷，減少跳步驟推斷造成的幻覺。
📊 輸出格式
建議
指定結構化輸出格式（Markdown / JSON），確保每次回應包含必要欄位。
🎯 置信度要求
建議
要求模型表達不確定性（high/medium/low），減少假陽性誤報。
⚖️ 平衡約束
重要
加入「大多數影片是正常的，正確回報無違規也是好答案」，防止確認偏誤。

3 System Prompt 範本

推薦入門用。結構清晰，適合直接給使用者看的場景。
你是一位專業的安全監控分析師，負責分析監控影像中的安全違規事件。 你的任務： 即使使用者的問題很簡短，也要主動、全面地分析以下違規行為： - 未授權穿越禁制區（未刷卡、翻越欄杆、從未授權出口進入） - 尾隨入侵（tailgating）：一人刷卡後另一人緊跟進入 - 借用他人門禁卡（piggybacking）：持卡人為他人刷卡開門 - 人員在非工作時段出現於限制區域 - 其他異常行為（打架、遺留物品、長時間徘徊） 分析步驟（請依序思考）： 1. 描述場景：環境類型、人數、時間線索 2. 追蹤人員動線：每個人如何移動、是否接近門禁或限制區 3. 辨識門禁設備與標誌：刷卡機、閘門、禁止進入標誌 4. 判斷是否有違規行為，並說明視覺依據 5. 給出最終結論 輸出格式： **場景描述**：[簡短描述] **違規判斷**：有 / 無 / 可疑 **違規類型**：[若有，列出類型] **視覺依據**：[具體描述你看到的畫面] **置信度**：高 / 中 / 低 **建議行動**：[通報 / 持續監控 / 無需動作] 重要原則：大多數監控影片是正常的，正常回報「無違規」是正確答案。
適合串接後端告警系統，輸出可直接 JSON.parse()。
你是安全監控 AI，專門分析影像中的門禁與限制區違規行為。 無論使用者如何描述問題，你都必須分析以下場景並以 JSON 格式輸出： 偵測範圍： - access_violation：未授權進入（未刷卡、強行進入） - tailgating：尾隨他人通過門禁 - card_sharing：持卡人替他人刷卡 - loitering：可疑徘徊超過 30 秒 - after_hours：非工作時間出現 輸出格式（嚴格遵守，不要輸出其他文字）： { "violation_detected": true 或 false, "confidence": "high" 或 "medium" 或 "low", "violations": [ { "type": "violation_type", "description": "具體行為描述", "location": "畫面中的位置描述", "persons_involved": 涉及人數 } ], "scene_summary": "場景概述", "recommended_action": "建議行動" } 若無違規，violations 為空陣列。 若影像不清楚，confidence 設為 "low" 並在 scene_summary 說明原因。
準確率最高，強制逐步推理，適合複雜場景或高誤報敏感環境。
你是資深安全稽核員，擅長從監控影片中發現微小的安全違規跡象。 使用者可能只問「有沒有問題」等模糊問題，但你必須執行完整的安全稽核分析。 【分析框架】 第一步 — 場景建立： - 這是什麼地點？（辦公室入口、機房、倉庫、停車場？） - 畫面中有幾個人？各自的位置？ - 有無門禁設備（刷卡機、指紋機、閘門）？ 第二步 — 行為追蹤： - 每個人的行動路線為何？ - 是否有人靠近門禁或限制區？ - 門是否被打開？誰打開的？打開後誰進去了？ 第三步 — 違規比對： 針對以下每一項明確回答「有 / 無 / 不確定」： □ 未刷卡 / 認證直接進入 □ 刷卡後有額外人員跟進（tailgating） □ 持卡人替他人刷卡（card sharing） □ 進入有禁止標誌的區域 □ 其他可疑行為 第四步 — 結論： - 最終判斷：有違規 / 無違規 / 需進一步確認 - 信心程度：高（清楚可見）/ 中（部分遮擋）/ 低（影像不清） - 若無法確定，說明原因（角度、光線、遮擋等） 禁止在沒有明確視覺依據的情況下判定違規。

4 減少幻覺：讓輸出貼近真實

⚠️ 核心問題： VLM 容易「補腦」——模型會根據 system prompt 的違規清單，在畫面不清楚的情況下仍傾向給出「有違規」的答案，造成大量假陽性。

技術 1：強制「先描述、再判斷」

要求模型在下結論前必須先引用視覺證據：

【規則】在給出任何違規判斷之前，你必須先完成： 1. 逐字描述你「實際看到」的畫面內容 2. 指出判斷依據的具體視覺證據（位置、動作、物件） 3. 才能得出結論 禁止推測你「沒有清楚看到」的事情。 若畫面不清楚、被遮擋、或無法確認，必須說明「無法判斷原因：XXX」。

技術 2：加入反幻覺約束語

重要限制： - 只描述畫面中實際可見的行為，不要根據直覺推測 - 若畫面解析度不足以判斷，請如實說明，不要猜測 - 不要因為「看起來可疑」就判定違規，需要明確的視覺證據 - 若整段影片無違規，請直接回答「無違規」並描述你看到的正常行為

技術 3：自我驗證步驟

在輸出結論後，再次確認： - 你描述的行為，是否在影片中有清楚的視覺支撐？ - 如果不確定，請降低 confidence 或改為「可疑，建議人工確認」

技術 4：跨幀一致性驗證（後端）

Python · 一致性檢查 
# 同一段影片取 3 組不同幀分析，結論不一致則標記人工複查
def cross_frame_verify(video_path, analyzer):
    results = [
        analyzer(sample_frames(video_path, offset=0)),
        analyzer(sample_frames(video_path, offset=0.5)),
        analyzer(sample_frames(video_path, offset=1.0)),
    ]

    violations = [r["violation_detected"] for r in results]

    if len(set(violations)) > 1:
        return {"status": "needs_human_review", "results": results}

    return results[0]

5 輸入優化：幀採樣策略

模型看到的幀品質直接決定輸出品質，固定 fps 的最大問題是可能剛好錯過 2-3 秒的關鍵事件。

問題症狀解法
採樣率太低 錯過尾隨事件（只發生 2 秒） 提高 fps 至 2-4fps，或用動作偵測採樣
採樣率太高 超過 token 上限，模型只看前幾幀 場景變化偵測採樣，或切片分析
關鍵幀模糊 運動模糊、低光，模型無法判斷 預處理銳化或跳過模糊幀
時間跨度太長 模型注意力分散到整段影片 切成 30 秒片段分批分析再彙整

動作區間採樣（推薦）

Python · OpenCV 動作偵測採樣 
import cv2

def extract_motion_frames(video_path, threshold=1000):
    """只保留有人移動的幀，節省 token 又不漏事件"""
    cap = cv2.VideoCapture(video_path)
    prev_frame = None
    key_frames = []

    while cap.isOpened():
        ret, frame = cap.read()
        if not ret:
            break

        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
        if prev_frame is not None:
            diff = cv2.absdiff(prev_frame, gray)
            motion = diff.sum()
            if motion > threshold:   # 有移動才保留
                key_frames.append(frame)

        prev_frame = gray

    cap.release()
    return key_frames

6 多步驟分析 Pipeline

單次問「有沒有違規」準確率不如拆步驟，每個 prompt 聚焦一件事：

🔵 步驟 1 — 人員偵測
"影片中有幾個人？描述每個人的位置與移動方向。"
🟡 步驟 2 — 門禁事件偵測（條件觸發）
"有人接近入口區域。描述他們如何通過： (a) 刷卡後進入 (b) 跟隨他人 (c) 未刷卡直接進入 (d) 無法判斷"
🔴 步驟 3 — 違規判斷（基於前兩步輸出）
"根據以上觀察： [注入步驟 1+2 的輸出] 是否符合違規定義？給出最終判斷與置信度。"
✅ 這樣每步驟的 prompt 更聚焦，模型不需要同時做偵測 + 推理 + 格式化，準確率明顯提升，代價是 API 呼叫次數增加 2-3 倍。

7 FPS 與 Token 計算

每幀消耗多少 Token？

Qwen2-VL 計算公式
每幀 token 數 = (width × height) / (14 × 14)
max_pixels = 360×420
~770 tok/幀
高畫質，快速消耗 budget
max_pixels = 256×256
~330 tok/幀
推薦，兼顧畫質與效率
max_pixels = 224×224
~256 tok/幀
最省 token，安監攝影機可用

模型安全幀數上限

模型 Context 可用幀數（770 tok/幀） 可用幀數（256 tok/幀）
Qwen2-VL-7B 32K ~36 幀 ~109 幀
Qwen2-VL-72B 128K ~161 幀 ~484 幀
Qwen2.5-VL-7B 32K ~36 幀 ~109 幀

動態 FPS 計算

Python · 自動計算安全 FPS 
def calculate_fps(video_duration_sec, model="7B"):
    max_frames = 36 if model == "7B" else 161
    safe_frames = int(max_frames * 0.9)   # 保留 10% buffer

    fps = safe_frames / video_duration_sec

    # 安全監控最低不能低於 0.5fps（否則漏掉 2 秒內的尾隨事件）
    fps = max(fps, 0.5)

    return round(fps, 2)

def should_split(duration_sec):
    return duration_sec > 60   # 超過 60 秒建議切片

9 優先實作順序

  • 1
    加入 System Prompt（任選一範本） 成本最低，效果最顯著。角色設定 + 違規清單 + 先描述再判斷規則三件套。
  • 2
    調整幀採樣：換用動作觸發採樣或降低 max_pixels 幀品質直接影響模型判斷，固定 fps 容易錯過關鍵 2 秒事件。
  • 3
    加入反幻覺約束語 + 平衡條款 防止 system prompt 的違規清單造成確認偏誤，大幅降低假陽性。
  • 4
    超過 60 秒的影片改為切片分析 需要一點工程，但效果明顯，避免模型因 token 超限只看前幾幀。
  • 5
    加入跨幀一致性驗證 對同一段影片多次採樣，結論不一致時標記人工複查。
  • 6
    改為多步驟 Pipeline + Few-shot 反例 收集 false positive 案例加入 system prompt，長期效果最好但需要標注資料。
