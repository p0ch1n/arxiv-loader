一、什麼是Token？理解計費的最小單位

Token是LLM處理文字的基本單位，也是所有費用的根源。理解Token，才能精準掌控成本。

Token的本質

現代LLM幾乎全部使用Byte Pair Encoding（BPE）或其變體進行分詞。算法從字符層級出發，反覆合併高頻相鄰字符對，最終形成包含30,000至100,000個詞彙的Token表。

核心換算公式

英文：1 Token ≈ 4個字元 ≈ 0.75個英文單字
1,000個英文單字約等於 1,300–1,500 Token
程式碼：因縮排與符號，密度較低，1.5–2× Token/詞
繁/簡體中文：等量資訊需要2–8倍英文Token數量

CJK語言的成本隱患

繁體中文用戶需要特別注意一個關鍵事實：中文Token消耗量是英文的2至8倍。1,000個漢字在GPT-4o的tokenizer下可能消耗1,500至4,000個Token，而等量資訊的英文版本只需約250個Token。這不是可以忽略的邊際差異，而是數倍的成本倍增器。

⚠ 中文開發者必讀

以中文為主要語言的AI應用，在相同規模下，Token消耗量可能是英文應用的3至6倍。不同模型使用不同的Tokenizer，同一段中文文字在OpenAI vs Claude vs Gemini下的Token數量可能差異顯著。請務必用目標模型的官方計算器預測實際成本。

「Lost in the Middle」現象

研究證明，LLM對上下文中段內容的注意力可下降30%以上。放在開頭和結尾的資訊效果最佳。廣告100K Token的上下文窗口，並不保證100K Token的有效理解。長上下文≠高質量推理。

為什麼輸出Token比輸入貴？

Token處理分為兩個階段：預填充（Prefill）階段並行處理所有輸入Token，相對高效；解碼（Decoding）階段則逐個生成輸出Token，每個Token需要數到數十毫秒。這個非對稱性解釋了為什麼輸出Token定價普遍比輸入高3至5倍——Claude Sonnet的比例是5:1（$3 vs $15）。

五大優化槓桿

三、成本優化的五大槓桿

系統性地疊加以下五個優化策略，可以將成本削減84%至91%。每個槓桿都有獨立的節省空間，且效果可以複合疊加。

01
模型分層路由
節省 60–70%

用輕量分類器判斷任務複雜度，將80%的簡單查詢路由到Haiku/Flash，10%的複雜任務才使用Opus。研究顯示，精心設計的級聯系統可實現87%的成本削減。

02
Prompt Caching
節省 60–90%

儲存重複系統提示的KV計算結果。Claude快取命中折扣90%（僅需$0.30/M vs $3/M），OpenAI自動快取折扣50%。每日10萬次相同系統提示，每日可節省逾$2,600。

03
Batch API
節省 50%（固定）

非即時任務改用批量API，OpenAI與Anthropic均提供50%固定折扣，結果24小時內返回。文件處理、內容審核、夜間分析的最佳選擇。

04
上下文壓縮
節省 50–70%

在注入主提示前先萃取/摘要檢索內容。LLMLingua等工具可實現5至20倍壓縮同時保持或提升準確率。RAG系統的必備優化。

05
輸出長度控制
節省 20–30%

設定max_tokens限制，要求JSON結構化輸出而非散文。結構化輸出比等量文字描述少30–50%的Token，消除「當然，以下是您要求的分析……」式的廢話前綴。

四、Prompt Caching深度解剖

KV快取的工作原理

每次LLM請求都要對輸入Token做注意力計算，生成鍵值對（KV pairs）。Prompt Caching將這些計算結果存起來，後續相同前綴的請求直接讀取快取，跳過重新計算。

實際案例計算

假設一個10,000 Token的系統提示，每天發送10萬次請求（使用Claude Sonnet 4.6）：

── 未使用快取 ──────────────────────────────────
每日成本 = 100,000 次 × 10,000 Token × $3.00/M
         = $3,000 / 天

── 使用快取（90% 命中率）───────────────────────
快取寫入（5分鐘TTL） = 10,000 Token × $3.75/M = $0.0375
快取命中 = 90,000 次 × 10,000 Token × $0.30/M = $27.00
快取未命中 = 10,000 次 × 10,000 Token × $3.00/M = $300.00
每日成本合計 ≈ $327.04 / 天

── 節省：~89%（*假設流量集中於同一TTL窗口內）───
真實案例

Anthropic的Claude Code本身在生產環境達到92%快取命中率，實現81%成本降低。快取+批量疊加使用，可將Claude Sonnet的有效輸入成本從$3.00/M壓縮到$0.15/M（原始定價的5%）。

五、進階策略：應用層語義快取

研究顯示，自建LLM推理的人力成本（SRE、MLOps、模型更新）佔總擁有成本的70–80%。單純比較GPU費用 vs API費用的算法是嚴重低估了自建的真實成本。在沒有專職AI平台工程師的團隊，自建往往比看起來昂貴得多。

七、ROI計算框架

基礎公式

── 每月Token成本估算 ─────────────────────────
月成本 = (平均輸入Token × 月請求量 × 輸入價格/M / 1,000,000)
       + (平均輸出Token × 月請求量 × 輸出價格/M / 1,000,000)

── 加上快取後 ───────────────────────────────
月成本 = (新鮮輸入Token × 月請求量 × 標準輸入價格/M / 1M)
       + (快取命中Token × 月請求量 × 快取讀取價格/M / 1M)
       + (平均輸出Token × 月請求量 × 輸出價格/M / 1M)

九、降價加速器：MoE與推測解碼

混合專家（MoE）架構的成本意涵

DeepSeek V3證明了MoE的威力：671B總參數，每次前向傳播只激活~37B個參數。推理成本等同於37B稠密模型，但效果媲美GPT-4o。這已開始迫使所有主要供應商加速自家的效率工程。

推測解碼（Speculative Decoding）

小型「草稿模型」並行提議多個Token，大型「驗證模型」一次確認或拒絕，接受的Token無需順序生成。2025年，推測解碼已從研究轉為生產標準。vLLM和TensorRT-LLM均原生支持。NVIDIA在H200 GPU上展示了3.6倍吞吐量提升——對自建推理用戶而言，等效降低50–67%的每Token成本。

結語

十、行動清單：下週就能做的優化

  • 盤點當前API帳單結構，確認輸入/輸出Token各佔多少
  • 檢查系統提示長度——若超過1,000 Token且高頻重複，立即啟用Prompt Caching
  • 評估查詢複雜度分布，是否80%的請求可以降級到輕量模型
  • 將非即時任務（文件處理、批次分析）遷移到Batch API
  • 在RAG應用中加入上下文壓縮層，目標削減30–50%的檢索Token
  • 所有API輸出改為結構化JSON，消除散文廢話，節省20–30%輸出Token
  • 在FAQ/分類場景評估語義快取，高命中率場景ROI極高
  • 建立Token成本監控儀表板，每日追蹤各接口消耗趨勢

LLM成本管理不是一次性配置，而是持續的系統工程。隨著推理成本持續下降，今日的奢侈在明日可能是常態——但不懂得優化的團隊，永遠在為低效率付費。
